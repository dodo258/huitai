## 仍有问题的 12 条

- **1｜没修好。网关地址和密钥分开配置时仍会泄露密钥。** pi 允许只给内置 provider 设置 `baseUrl`，由环境变量提供密钥。会话台看到配置里没有 `apiKey` 就跳过该项，随后按环境变量名向原厂发送鉴权请求。Hermes 把 `KIMI_BASE_URL` 写在账号的 `.env`、把密钥放在进程环境时也有同样结果。见 `src/quota/keys.rs:284`、`src/quota/keys.rs:391`、`src/quota/keys.rs:191`、`src/quota/balance.rs:387`。[pi 官方配置说明](https://docs.pi.dev/latest/models#configure-a-compatible-endpoint)

- **3｜没修好。工作会话仍可能使用个人登录。** 非默认会话目录现在能携带登录目录。但 Qwen 的运行目录若恰为默认的 `~/.qwen`、`QWEN_HOME` 单独指向工作登录，恢复命令会省略或清掉工作登录变量。OpenCode 显式使用默认数据库、另设 `XDG_DATA_HOME` 时同理。OpenCode 2.x 也仍会自动发现共享后台服务，已有服务持有的会话可能属于另一账号。见 `src/core/dirs.rs:141`、`src/ui/runtime.rs:425`、`src/sources/opencode.rs:418`、`DECISIONS.md:727`。[OpenCode 后台服务说明](https://opencode.ai/docs/troubleshooting/#service-files)

- **4｜没修好。裸 ID 命中旧缓存时仍会导错账号。** 实测先索引默认账号，再为工作账号加入同 ID、不同正文的会话。此时导出裸 ID 退出码为 0，正文来自默认账号；刷新索引后才报告歧义。导出只在缓存零命中时扫描，缓存里仅有一条不足以证明所有启用账号中只有一条。见 `src/cli/export.rs:28`、`src/cli/export.rs:96`、`src/index/mod.rs:244`。

- **5｜没修好，并修出新问题。导出仍能覆盖整库。** 当前 JSONL 及其软硬链接已受保护，但校验只比较当前 `Session.path`。Hermes 和 OpenCode 的该字段为空，`-o` 指向实际会话数据库时，程序会用 Markdown 替换整库。其他会话文件和厂商配置也未受这项检查保护。见 `src/cli/export.rs:49`、`src/cli/export.rs:129`、`src/sources/hermes.rs:444`、`src/sources/opencode.rs:637`。

  新的临时文件写法还改变了既有目标的行为。实测在可写目录里，0444 只读文件被覆盖，命名管道被换成了普通文件。覆盖私有导出时，临时文件写完后才收紧权限，在共享目录、常见的 022 umask 下，其他本地用户在此期间可读正文。若临时文件名已被普通文件占用，创建失败后的清理还会删除那个已有文件。见 `src/cli/export.rs:157`、`src/cli/export.rs:161`、`src/cli/export.rs:163`、`src/cli/export.rs:166`。

- **6｜没修好。一次 PTY 输出仍可被算成两份认领证据。** 同一批输出带标题或响铃时，守护进程可以同时发出 `Output` 和 `Title` 或 `Bell`。界面把两条事件各记作一次输出。同账号、同项目内，另一终端的候选会话在匹配窗口更新两次，仍可能绑定到这个进程，随后回车或结束操作都会作用于错的对话。见 `src/host/daemon.rs:1452`、`src/host/daemon.rs:1454`、`src/ui/runtime.rs:1710`、`src/ui/app.rs:2430`。

- **7｜没修好。升级后仍会认错或重复启动工作会话。** 旧工作进程记的是原生 ID。只要默认账号有同 ID 副本，程序就先认给默认账号，即使两条会话的项目目录不同；工作账号那一行仍可再起 CLI，中断记录也可能挂错行。另一个情形无需重名：v0.1.3 新建的 Codex 工作会话使用无账号前缀的临时 ID，新版要求临时 ID 的账号与列表账号相等，仍接不回原进程。见 `src/ui/runtime.rs:463`、`src/ui/runtime.rs:656`、`src/ui/runtime.rs:701`、`src/ui/runtime.rs:890`；旧版见 `1f71dfd:src/ui/runtime.rs:436`。

- **8｜没修好。tmux 透传仍有提前补标题的边界。** 原报告中的 BEL 和转义后的内层 ST 已正确处理。但 tmux 在 DCS 正文里把 CAN、SUB 当数据，会话台遇到它们就回到安全边界。读取恰停在这里且状态变化时，标题仍会插进外层透传。见 `src/host/scan.rs:241`、`src/host/scan.rs:394`、`src/host/daemon.rs:347`。[tmux 的 DCS 状态表](https://github.com/tmux/tmux/blob/master/input.c#L646-L664)

- **9｜没修好，并修出新问题。旧版保存设置后，两次读取就会清掉手动账号。** 用一条手动账号模拟 v0.1.3 更改普通设置并丢掉 `accounts` 字段。新版第一次读取仍有 1 条，第二次读取变为 0，`accounts.json` 也为空。第一次读取写入了新的设置快照，第二次把同一个缺失字段误判成用户主动删除。一次 `ai list` 就会经过这两次读取。见 `src/core/config.rs:160`、`src/core/config.rs:166`、`src/core/config.rs:180`、`src/cli/query.rs:67`、`src/sources/trash.rs:88`、`src/sources/mod.rs:383`。

  标注分文件已解决旧版把整份标注移走的问题，但新版的只读查询漏读 `annotations-more.json`。实测给 Antigravity 会话改名并归档后，`ai list --json` 仍给出原名和 `archived: false`，按新标题运行 `ai search` 返回空数组。见 `src/index/notes.rs:186`、`src/index/notes.rs:402`、`src/index/mod.rs:188`。

- **13｜没修好，并修出新问题。第二个窗口仍会显示过期的绑定。** 窗口 B 收到启动事件后会补取列表，但若此时 A 尚未保存认领，B 又漏看了一批历史变化，之后不会主动读回 A 的认领。B 仍可能缺少实时预览，按 `x` 提示没有后台进程；在绑定有歧义时按回车才会再读盘。反过来，A 撤销错误认领后，B 已采纳的绑定也不会因磁盘记录删除而撤销，同一进程仍在时，回车可能接错。见 `src/ui/runtime.rs:1672`、`src/ui/runtime.rs:882`、`src/ui/app.rs:2317`、`src/ui/app.rs:2436`。

- **16｜没修好。主账号回退已修，Hermes 的 Kimi 余额仍会漏。** 未选中会话时，顶栏现在取主账号。但 provider 表仍缺 `kimi-coding-cn`，且把 `kimi-coding` 固定映射到 Kimi Code。旧密钥实际查到 Moonshot 余额时，顶栏会过滤掉该行。见 `src/ui/app.rs:480`、`src/quota/keys.rs:214`、`src/quota/keys.rs:500`、`src/quota/balance.rs:203`。[Hermes 的 Kimi 端点定义](https://github.com/NousResearch/hermes-agent/blob/main/hermes_cli/auth.py#L177-L181)

- **22｜没修好，并修出性能回归。取一条 Antigravity 预览仍受整段历史拖累。** 第一条 SQL 会读取所有块的正文长度。保持最新短回复不变，仅将旧块从 40 字节增至 9 MiB，该 SQL 在系统 SQLite 中的峰值分配便从约 0.18 MiB 升至 26.6 MiB。最新消息本身超过 8 MiB 时也会整条解码后才截短。另外，尾部每个只含换行的步骤都会让单条预览再启动一次 SQLite；调试构建中，尾部增加 100 个这样的步骤，三次测量的中位数从 23 毫秒升至 786 毫秒。见 `src/sources/antigravity.rs:219`、`src/sources/antigravity.rs:252`、`src/sources/antigravity.rs:262`、`src/sources/antigravity.rs:338`、`src/sources/antigravity.rs:495`。

- **25｜修出新问题。成功导出的正文已转义，歧义报错仍能改变终端。** 两个账号有同 ID 时，新增诊断会把会话标题原样写到标准错误。Claude 标题可取自首问，因此历史里的终端控制字符仍会在报错时生效，即使标准输出已经重定向。见 `src/cli/export.rs:55`、`src/cli/export.rs:111`、`src/cli/mod.rs:128`、`src/sources/claude.rs:150`、`src/sources/jsonl.rs:42`。
