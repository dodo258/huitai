## 原文

审计基于当前提交 `17ac036`，全程只读。最需要先修的是三处：读取 Claude 备份时可能误删其他目录的文件，升级可能原地替换正在使用的 CLI，以及自动升级可能装入未经检查的大版本。以下均为静态调用链核对，未运行真实升级、删除或放回操作。

## 各家 CLI 升级

1. **探测 npm 时会执行项目里的同名程序。** 界面虽然过滤了 PATH 里的相对目录，随后运行 `npm prefix -g` 却仍继承原始 PATH。命令行入口也在过滤前调用 npm。从 PATH 含当前目录或相对 `bin` 的项目启动时，只要打开版本检查，就会执行该位置的 `npm`，即使自动升级已关闭。建议先过滤 PATH，再用解析出的可信绝对路径探测和执行。见 [src/clis/locate.rs:71](src/clis/locate.rs:71)、[src/clis/locate.rs:25](src/clis/locate.rs:25)。

2. **探测的是一份 CLI，实际升级的可能是另一份。** 从带项目 `node_modules/.bin` 的环境启动时，项目内的 npm 包会通过全局前缀检查，实际却执行全局安装，改了全局 CLI，项目里的旧版仍在。双 Homebrew 也有同类问题：识别出了 CLI 所属的 Cellar，执行时却调用 PATH 上第一份 `brew`。建议把安装计划绑定到已核实的管理器绝对路径和全局安装根，项目本地包只提示。见 [src/clis/detect.rs:327](src/clis/detect.rs:327)、[src/clis/detect.rs:88](src/clis/detect.rs:88)、[src/clis/plan.rs:81](src/clis/plan.rs:81)。

3. **“不跨大版本”只检查缓存，实际安装追随 `@latest`。** 例如缓存允许从 `1.2` 升到 `1.3`，缓存有效期内仓库发布 `2.0`，下一次升级就会装入 `2.0`，复查还会报告成功。建议安装经过检查的精确版本；渠道无法固定目标时，只提示手动升级。见 [src/clis/plan.rs:57](src/clis/plan.rs:57)、[src/clis/detect.rs:88](src/clis/detect.rs:88)、[src/clis/upgrade.rs:206](src/clis/upgrade.rs:206)。

4. **运行中的会话会漏过保护。** 自动升级、顶栏一键升级和 `ai update --all` 都只在整批开始时查一次托管列表。第一家升级期间打开第二家的 npm 会话，轮到第二家时仍会原地替换文件，运行中的 CLI 后续加载模块时可能出错。直接在其他终端启动的非托管会话也不在名单里。建议每家执行前重新检查，并让托管会话启动与原地升级共用厂商级互斥；对非托管进程补充检查。见 [src/ui/runtime/workers.rs:413](src/ui/runtime/workers.rs:413)、[src/ui/runtime/workers.rs:457](src/ui/runtime/workers.rs:457)、[src/cli/cli_upgrade.rs:42](src/cli/cli_upgrade.rs:42)、[src/host/client.rs:69](src/host/client.rs:69)。

5. **两个会话台可能同时拿到同一厂商的升级锁。** 锁文件先创建、后写 PID。另一个进程在中间读到空文件，会把有效锁当残留删除；两个进程同时清理旧锁时，也可能删掉刚重建的锁。结果是两个安装器同时操作同一份 CLI。建议对固定文件使用内核 `flock`，持有文件描述符直到安装结束，释放时保留锁文件。见 [src/clis/upgrade.rs:281](src/clis/upgrade.rs:281)、[src/clis/upgrade.rs:297](src/clis/upgrade.rs:297)。

6. **退出会话台会丢失升级监护，十分钟超时也有缺口。** 升级中按 `q` 退出，独立进程组里的安装器可能继续运行，但锁里记录的是已经退出的会话台 PID。此时重开会话台可再次升级，原安装也失去了超时监护。另外，安装命令先退出、后台辅助进程仍持有输出管道时，读取线程的 `join` 没有期限，升级线程和锁会一直等。建议由生命周期覆盖整个安装过程的进程持锁，并让同一截止时间覆盖进程退出和输出读取。见 [src/ui/runtime/workers.rs:334](src/ui/runtime/workers.rs:334)、[src/clis/upgrade.rs:287](src/clis/upgrade.rs:287)、[src/core/exec.rs:60](src/core/exec.rs:60)、[src/core/exec.rs:119](src/core/exec.rs:119)。

7. **“同一版自动只试一次”会失效，严重时会连续重跑。** 自动失败后再手动重试失败，手动结果会覆盖自动尝试记录。不同窗口同时写不同厂商的结果，也会因整份 JSON 读改写而丢记录。若安装失败且结果文件持续无法替换，写入错误会被忽略，后台随后以零等待再次执行。建议在厂商锁内先持久记录本次自动目标，手动结果单独保存；记录失败时停止本轮自动安装并提示。见 [src/clis/upgrade.rs:59](src/clis/upgrade.rs:59)、[src/clis/upgrade.rs:160](src/clis/upgrade.rs:160)、[src/clis/upgrade.rs:335](src/clis/upgrade.rs:335)、[src/ui/runtime/workers.rs:361](src/ui/runtime/workers.rs:361)。

8. **自动升级开关在两种情况下与界面不一致。** 已关闭自动升级时，配置暂时读不了或 JSON 损坏，后台会按默认“开”执行安装；反过来，启动时关闭了版本检查，在当前窗口重新打开，升级线程又始终不会启动。建议已有配置读取失败时暂停自动安装并提示，设置变更后唤醒或启动工作线程。见 [src/ui/runtime/workers.rs:350](src/ui/runtime/workers.rs:350)、[src/ui/runtime/workers.rs:481](src/ui/runtime/workers.rs:481)、[src/ui/runtime.rs:234](src/ui/runtime.rs:234)、[src/ui/runtime.rs:1326](src/ui/runtime.rs:1326)。

9. **无法比较的版本会被报成“已是最新”或“升级成功”。** 本机是 `1.2.3-beta.1` 时，即使已发布正式版，`ai update <家>` 也会报“已是最新”并返回成功。升级后的复查同样把“无法比较”当成达到目标。建议显式区分“小于、等于、大于、无法比较”，最后一种返回无法验证。见 [src/cli/cli_upgrade.rs:82](src/cli/cli_upgrade.rs:82)、[src/clis/upgrade.rs:206](src/clis/upgrade.rs:206)、[src/core/release.rs:59](src/core/release.rs:59)。

## Claude 对话备份和放回

1. **读取备份可能改权限并删除其他目录的文件。** 如果备份目录里的 `.open` 是指向其他目录的符号链接，扫描一条“只剩备份”的对话就会跟随它，可能把目标目录改成 `0700`，随后删除其中访问时间超过一小时的文件。清理时没有核对文件名是否由会话台生成。建议拒绝备份内部的目录链接，并把清理限制为已确认属于会话台的临时文件。见 [src/sources/backup.rs:132](src/sources/backup.rs:132)、[src/sources/backup.rs:249](src/sources/backup.rs:249)、[src/sources/backup.rs:297](src/sources/backup.rs:297)。

2. **按 `P` 可能把对话明文放到 Claude 项目目录之外。** 原项目子目录后来换成符号链接，且链接目标没有同名文件时，放回会沿链接成功写入。最终文件的排他改名能防覆盖，但无法约束父目录。建议从已确认的账号 `projects` 目录句柄打开项目子目录，拒绝跟随子目录链接，并在同一句柄下创建临时文件和排他改名。见 [src/sources/claude.rs:206](src/sources/claude.rs:206)、[src/sources/backup.rs:169](src/sources/backup.rs:169)。

3. **后台备份能让刚删除的对话重新出现。** 压缩已经打开原文件时，用户把该对话移进回收站。删除只收走当时存在的文件，压缩随后仍能完成并重新发布备份。重扫后对话以“只剩备份”出现；若旧备份也进了回收站，按 `u` 还会因路径被重新占用而失败。建议按账号和会话串行处理备份提交与删除，在锁内确认原文件仍是开始压缩的那一份。见 [src/sources/backup.rs:94](src/sources/backup.rs:94)、[src/sources/claude.rs:136](src/sources/claude.rs:136)、[src/sources/trash.rs:118](src/sources/trash.rs:118)。

4. **按 `P` 遇到临时文件重名，会删掉一个原本就存在的文件。** 临时名由 PID 和进程序号构成。若上次中断留下同名文件、PID 又被复用，`create_new` 会正确拒绝创建，错误分支却无条件删除该路径。受影响的是 Claude 项目目录里的同名临时文件。建议碰撞时换名，只清理本次确实独占创建成功的文件。见 [src/sources/backup.rs:182](src/sources/backup.rs:182)、[src/sources/backup.rs:257](src/sources/backup.rs:257)、[src/sources/backup.rs:286](src/sources/backup.rs:286)。

5. **备份校验失败时，会先删旧备份再尝试重建。** 校验把临时读取错误也当成文件损坏。如果这时无法重新读取原件、磁盘已满，或重建中断，旧备份已经丢失。这个分支恰好用于接近 Claude 清理期限的对话。建议强制写入新的临时备份，压缩、同步和校验都成功后再原子替换旧件。见 [src/sources/claude.rs:194](src/sources/claude.rs:194)、[src/index/backup.rs:63](src/index/backup.rs:63)。

6. **启动时的首轮备份可能静默漏掉对话。** 开启全量备份后，如果存在尚未入索引的新对话，或索引刚重建，备份线程可能在首扫完成前就读完旧列表。首扫完成只刷新界面；十分钟内直接退出，本次就没有备到这些对话。建议在 Claude 首次索引提交后触发一次备份。见 [src/index/backup.rs:50](src/index/backup.rs:50)、[src/ui/runtime/workers.rs:505](src/ui/runtime/workers.rs:505)、[src/ui/runtime.rs:1456](src/ui/runtime.rs:1456)。

在审查的升级命令构造中，未发现直接调用 `sudo`，也未发现厂商参数或远端版本字符串被拼成 shell 指令。正常目录布局下，`P` 对最终同名文件使用排他改名。备份功能读取 `~/.claude/settings.json` 获取保留天数，未发现直接写回该文件的代码。见 [src/clis/plan.rs:77](src/clis/plan.rs:77)、[src/sources/trash.rs:367](src/sources/trash.rs:367)、[src/sources/claude.rs:246](src/sources/claude.rs:246)。
