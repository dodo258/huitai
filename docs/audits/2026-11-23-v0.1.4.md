# 会话台 v0.1.4 发布前审计

**建议暂缓发布。** 当前版本能把自建网关的密钥发给原厂，也能在用户选择工作账号时导出个人账号的对话。另有覆盖原始会话文件、接错托管进程和破坏非标题终端序列的路径。

审计范围为 `1f71dfd..25c1d5c`。下列行号指向候选版本，跨版本检查使用了实际 v0.1.3 代码。

## P1 · 发布前应修复

1. **查余额会把自建网关密钥发给原厂。** `src/quota/keys.rs:172`、`src/quota/keys.rs:208`、`src/quota/keys.rs:302`。pi 允许保留内置 provider 名并覆盖 `baseUrl`，Hermes 也支持覆盖 Kimi、GLM 的地址。会话台按 provider 名或密钥变量名认厂商，随后用这把密钥向原厂鉴权。域名白名单只校验选中的余额接口。启动会话台就会查询，无需打开 `$` 面板，原厂返回 401 时也已经收到密钥。建议先按账号解析生效的凭据和服务地址，仅在能确认密钥归属相应官方服务时查询。[pi 模型配置](https://docs.pi.dev/latest/models) · [Hermes 地址解析源码](https://github.com/NousResearch/hermes-agent/blob/main/hermes_cli/auth_zai_kimi.py)

2. **Claude 的 OAuth 凭据可进入 curl 追踪文件。** `src/quota/claude.rs:75`、`src/quota/claude.rs:193`、`src/quota/claude.rs:200`。本次把用量查询扩展到非默认账号，沿用了会读取用户 `.curlrc` 的调用。缓存未命中且启用了文件追踪时，从标准输入传入的 Authorization 请求头也进入追踪文件。建议复用余额渠道调用 `/usr/bin/curl` 的方式，把禁用默认配置的 `-q` 放在第一个参数。[curl 追踪说明](https://curl.se/docs/manpage.html#--trace-ascii) · [curl 默认配置开关](https://curl.se/docs/manpage.html#--disable)

3. **工作账号的会话目录和登录身份可以分属两个账号。** `src/core/dirs.rs:42`、`src/core/dirs.rs:109`、`src/sources/mod.rs:263`。从带临时环境变量的终端启动会话台，再开普通新标签页恢复对话，OpenCode 只收到数据库路径，原先由 `XDG_DATA_HOME` 选中的 `auth.json` 没有跟过去。Qwen 同时设置不同的 `QWEN_RUNTIME_DIR` 和 `QWEN_HOME` 时也只带前者。结果是工作会话使用新标签页的个人凭据，或要求重新登录。OpenCode 2.x 若复用另一账号已启动的后台服务，还会访问该服务持有的会话。建议为每个账号保留历史、认证和服务实例所需的目录，恢复、新建和复制命令使用同一份账号环境。[OpenCode 认证源码](https://raw.githubusercontent.com/anomalyco/opencode/v1.19.6/packages/opencode/src/auth/index.ts) · [OpenCode 数据目录](https://raw.githubusercontent.com/anomalyco/opencode/v1.19.6/packages/core/src/global.ts) · [OpenCode 后台服务](https://opencode.ai/docs/troubleshooting/#service-files) · [Qwen 存储源码](https://github.com/QwenLM/qwen-code/blob/v0.28.3/packages/core/src/config/storage.ts#L151-L194)

4. **从工作账号复制的 ID 可以静默导出个人对话。** `src/cli/export.rs:60`、`src/sources/account.rs:213`、`README.md:140`。按说明从工作会话的 `c` 恢复命令取原生 ID；若默认账号也有同 ID 的历史，查找先把默认账号当作精确匹配并返回。用两份同 ID、不同正文的隔离样本实测，导出成功，内容来自默认账号。建议提供带厂商和账号的导出标识，裸 ID 在全部可见账号中唯一时才接受，歧义时列出可选账号。

5. **指定导出目标能覆盖原始会话。** `src/cli/export.rs:44`。若 `-o` 指向本次读取的 JSONL，或已有导出路径是指向它的链接，程序先读出对话，再把原文件截断并写成 Markdown，破坏 CLI 的恢复记录。覆盖普通既有导出时，写入中途失败也会损失旧内容。建议拒绝厂商数据及配置目标，校验源文件与目标的文件身份，并用同目录临时文件写完后原子替换普通导出。

6. **新建对话能认领另一个终端的对话。** `src/ui/app.rs:2391`、`src/ui/app.rs:2417`、`src/ui/runtime.rs:783`。同账号、同项目中，托管进程 A 仅输出一次，外部对话 B 的历史随后变化两次。只要两次都落在同一次输出的匹配窗口内，算法就把这一次输出算作两份证据。已用当前代码复现 B 被绑定到 A；此后从 B 所在行回车会接进 A，输入或结束操作会作用于错误进程。建议按独立输出事件匹配并消费证据，所有权仍不明确时保留歧义状态。

7. **升级后可能为仍在运行的工作会话再起一个 CLI。** `src/sources/account.rs:155`、`src/ui/runtime.rs:447`、`src/ui/runtime.rs:779`。v0.1.3 在自定义目录下托管会话时保存原生 ID，新版列表给同一会话加了账号前缀。已有进程按 ID 对不上，回车会再次恢复同一历史；旧中断记录也会从工作账号的恢复列表消失。若默认账号恰有同 ID，旧记录还会匹配到默认账号。建议给旧托管和中断记录共用一套映射，结合厂商、原生 ID、项目和账号证据，无法唯一定位时阻止重复启动。

8. **状态标题能插进尚未结束的 DCS 数据。** `src/host/scan.rs:413`、`src/host/scan.rs:429`、`src/host/daemon.rs:347`。tmux 透传的外层 DCS 可以包含以 BEL 结束的内层 OSC。若一次 PTY 读取刚好停在该 BEL，已验证扫描器在外层 ST 到来前就报告安全边界。此时状态变化会把标题插入原始数据，破坏非标题序列。建议分别跟踪 OSC、DCS 等字符串的终止规则，并覆盖透传转义、跨读取分块和等待补发标题同时发生的情况。[tmux 透传说明](https://github.com/tmux/tmux/wiki/FAQ#what-is-the-passthrough-escape-sequence-and-how-do-i-use-it) · [XTerm 控制序列](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html)

## P2 · 账号、升级与多窗口

9. **旧版会移走新版的整份标注，也会抹掉手动账号配置。** `src/core/vendor.rs:17`、`src/index/notes.rs:115`、`src/core/config.rs:33`。实测 v0.1.3 打开含一条 Antigravity 标注的共享文件后，把整个 `annotations.json` 改名为损坏备份，原有 Claude 标注也随之消失，需手工恢复。另一次实测中，旧版保存普通设置后，`config.json` 中的 `accounts` 被删掉。建议将旧版无法往返保存的新厂商标注和账号配置写入独立文件，并兼容已写出的新版数据。

10. **升级会找错旧标注目录。** `src/index/mod.rs:200`、`src/core/dirs.rs:36`。同时设置自定义 `CODEX_HOME` 和 `XDG_DATA_HOME` 时，v0.1.3 算旧目录名只受前者影响，新版迁移还计入 OpenCode 的 XDG 路径。同一组合实测得到两个不同目录名，原有工作账号的改名、置顶和归档留在旧目录。建议按 v0.1.3 的环境解析规则定位旧文件，再映射到新版账号。

11. **在一个账号隐藏对话会同时隐藏另一个账号的副本。** `src/sources/account.rs:230`、`src/sources/trash.rs:291`。对于数据库型来源，回收站以厂商和原生 ID 判断隐藏状态。用两个 Antigravity 账号的同 ID 样本实测，删除工作账号那条后，两条同时从列表消失，底层数据库仍在。建议按账号或规范化数据库路径记录隐藏状态，恢复时也使用同一身份。

12. **两个窗口同时保存认领结果会丢一条。** `src/ui/runtime.rs:739`、`src/ui/runtime.rs:750`。两个进程各自读旧 `claims.json`、修改不同条目再替换文件，两边均返回成功，后写者覆盖先写者。双进程验证连续三次均丢一条，重启后无法用该映射接回会话。读取出错时当前实现还会从空表覆盖。建议给整个读、改、写过程加跨进程锁，读取异常时保留原文件并报告错误。

13. **已经打开的第二个会话台认不出随后新建的对话。** `src/ui/runtime.rs:1159`、`src/ui/runtime.rs:1514`、`src/host/client.rs:435`。窗口 B 已订阅时，A 新建需要临时 ID 的会话。B 收到的 Started 只有 ID 和 PID，缺少项目和厂商，认领计算跳过它；现代守护进程的事件订阅也不会定时补发列表。即使 A 已认领，B 仍可能拒绝接入，直到重连。建议遇到未知临时 ID 时补取 List，并同步其他窗口已经保存的绑定。

## P2 · 余额、动态、历史与搜索

14. **换密钥后仍会显示上一账号的余额。** `src/quota/keys.rs:54`、`src/quota/balance.rs:239`、`src/quota/balance.rs:250`。两个终端给同名环境变量设置不同密钥，或在原文件位置轮换密钥，持久缓存仍按来源名称命中。离线模拟中第二把密钥没有触发查询，直接拿到第一把的读数；限流退避也会串用。建议环境变量来源仅在进程内按实际凭据复用，文件来源变更时失效，并保持密钥及其指纹不落盘。

15. **OpenRouter 周期限额会在仍有余额时显示耗尽。** `src/ui/balance.rs:120`、`src/ui/balance.rs:405`。接口的 `usage` 是累计用量，`limit_remaining` 是当前剩余额度。用累计 $50、日限额 $10、剩余 $9 的响应实测，面板进度条满格，doctor 显示已用 $50 / $10。面板还把数值 0 的限额显示为“不限额”。建议按本期剩余量推算已用，区分零限额与空限额，两个入口共用计算结果。[OpenRouter 官方字段说明](https://openrouter.ai/docs/api_reference/limits)

16. **顶栏会选错主账号，也会漏掉 Hermes 的 Kimi 余额。** `src/ui/app.rs:480`、`src/quota/keys.rs:374`、`src/quota/keys.rs:390`。工作号为主账号且默认目录也存在时，选中项目标题或列表为空就显示默认号额度，已用双账号复现。另一个独立触发条件是 Hermes 使用官方 `kimi-coding-cn`，或在 `kimi-coding` 下使用旧 Moonshot 开放平台密钥，此时查到的读数无法匹配顶栏或只查询错误服务。建议保留“未选会话”状态并回退到主账号，Hermes 则按上游有效端点和 provider 别名匹配读数。[Hermes provider 注册表](https://github.com/NousResearch/hermes-agent/blob/main/hermes_cli/auth.py#L177-L181)

17. **数据库型会话的「此刻」会停在第一次读取。** `src/ui/runtime.rs:1715`、`src/ui/runtime.rs:1747`、`src/sources/hermes.rs:439`、`src/sources/opencode.rs:632`。Hermes 和 OpenCode 的会话路径为空，刷新线程却只比较该路径和对应 WAL 的文件状态。只要同一会话持续可见，后续回复和工具状态就无法触发重读。Antigravity 使用产物目录，仅修改数据库正文时也有相同问题。建议由适配器提供实际数据库/WAL 或会话修订号作为刷新依据，成功读取后再记录版本。

18. **并行工具乱序返回时，「此刻」会显示已完成的工具。** `src/sources/claude.rs:251`、`src/sources/moment.rs:139`。读取调用和结果时丢掉关联 ID，每次返回都移除最早的调用。用 Claude 格式样本验证，先启动慢、快两个工具，快工具先完成，面板仍显示快工具正在运行。建议保留调用 ID，按结果的 `tool_use_id` 移除对应调用。[Anthropic 工具结果格式](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls)

19. **Kimi 撤销的首问仍会出现在列表和导出标题中。** `src/sources/kimi.rs:314`、`src/sources/kimi.rs:337`、`src/sources/kimi.rs:350`。没有人工标题的长对话里，首问位于文件头、撤销记录位于尾部时，两段独立计算；只要仍数到用户消息就跳过完整重放。包含撤销记录和新首问的隔离样本中，导出正文正确，标题仍含被撤销的文字。建议在撤销跨越读取窗口时重放，按仍然有效的首问生成标题并提升解析版本。[Kimi Code 撤销命令](https://github.com/MoonshotAI/kimi-code/blob/main/docs/en/reference/slash-commands.md)

20. **OpenCode 预览能读出的整段文字，导出时会静默消失。** `src/sources/opencode.rs:260`、`src/sources/opencode.rs:796`。旧格式数据库的文本块中只要含一个孤立 UTF-16 代理项，全文解析就丢弃整个块。以仓库已有边界样例构造数据库，预览保留了坏字符两侧的正文，实际 `ai export` 两侧文字都没有。建议复用预览的字段提取与坏字符替换逻辑，保留其余正文，并提升解析版本。现成样例见 `tests/sources_opencode.rs:517`。

21. **Antigravity 列出的部分历史无法回车打开。** `src/sources/antigravity.rs:177`、`src/ui/runtime.rs:429`、`src/host/daemon.rs:817`。工作区列表为空、或只有无法转成本机路径的 URI 时，扫描仍返回会话，但工作目录为空。回车后守护进程直接报“项目目录不存在”，尚未执行 agy。建议在恢复前允许选择有效的本地工作目录，对只能查看的记录明确提示。[Antigravity 官方恢复说明](https://antigravity.google/docs/cli/commands/resume/)

22. **Antigravity 只预览一条也会读完整段历史。** `src/sources/antigravity.rs:208`、`src/sources/antigravity.rs:383`、`src/sources/antigravity.rs:389`。查询先把全部正文转成十六进制、读回并解码，最后才取所需条数。隔离样本增加 8 MiB 历史后，同样只取一条预览，当前调试构建的测试进程峰值内存由约 7 MiB 升至 48 MiB。长会话会直接拖累列表预览。建议从最新块倒序读取，达到消息数和字节预算就停止。

23. **停用账号的缓存可以挤掉当前账号的全部正文搜索结果。** `src/index/mod.rs:257`、`src/index/mod.rs:264`。全文检索先取前 300 条，再剔除未启用账号。用 300 条已停用账号记录和 1 条可见记录实测，同一搜索词在界面上限下返回 0 条，把上限调大才返回那条可见记录。建议在排序、限量前过滤可用账号。

24. **有正文命中的结果仍会缺少片段，或保留过期片段。** `src/index/snippet.rs:29`、`src/index/store.rs:79`、`src/ui/app.rs:811`、`src/ui/app.rs:866`。实测搜索 `cafe` 能命中仅含 `café` 的正文，但片段按 ASCII 子串查找，返回空。另外，保持查询词不变时，即使来源正文已经更新，已有片段仍按会话 ID 复用。建议片段使用与 FTS 一致的分词和归一化规则，并按会话修订号更新缓存。[SQLite FTS5 分词规则](https://www.sqlite.org/fts5.html#unicode61_tokenizer)

25. **直接运行 `ai export` 会让终端解释正文里的控制字符。** `src/export/mod.rs:115`、`src/cli/export.rs:49`。历史消息包含真实终端转义字符时，默认输出将其原样写入当前终端，复制进对话的终端输出可以改变当前窗口标题或擦掉屏幕内容。建议输出目标为交互式终端时转义控制字符，保留换行和制表；导出到文件或管道时保留正文原样。[XTerm 控制序列](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html)

## P3 · 导出完整性说明

26. **按消息条数截断时，Markdown 错报“只导出了最后 32 MB”。** `src/export/mod.rs:96`、`src/sources/hermes.rs:321`、`src/sources/opencode.rs:377`、`src/sources/antigravity.rs:390`。例如 2,001 条很短的 Hermes 消息就会触发 2,000 条上限，导出说明却把缺失原因归为文件过大。建议让适配器返回截断原因和实际限额，或统一提示“更早的消息未导出”。
