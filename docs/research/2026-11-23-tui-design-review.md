# 会话台 TUI 视觉与交互评审

**有差距，最明显的地方是列表的主次和顶栏的信息取舍。** 在 Gemini 首图里，我很容易认出当前厂商，也能看懂右边正在跑测试。但如果任务换成「找到需要我回复的那条」，视线就要从顶栏的 `◆2 等你` 移到列表右侧找菱形，再横跨半屏读回左侧标题。相比之下，Yazi 能让我顺着高亮行直接找到文件，GitUI 能让我从底栏直接读出回车会对选中的内容做什么。会话台最值得缩短的，就是这段从**看见状态**到**认出对象**的距离。

**现有设计值得保留。** 随厂商变色的「会话台」印章有辨识度，尤其在 Claude 橙、Codex 蓝、pi 紫之间切换时很有效。左右两栏只靠底色就能分开，中文的「等你」「接着聊」「回到它」也比生硬的状态术语亲切。深色的暖灰字和浅色的中性灰底都成立。当前实现已经扩展到八个可见厂商，四级灰阶也比初版方案更易读，后续应以实际主题为准。[界面方案](docs/specs/huitai-v1.md:124) · [当前主题](src/ui/theme.rs:55)

## 六个值得借鉴的终端界面

我从 Ratatui 作品库、Terminal Trove 和 Charm 的 Bubble Tea / Lip Gloss 生态对照了六个作品。下面各取一个能用在会话台上的设计决定。[Ratatui App Showcase](https://ratatui.rs/showcase/apps/) · [Terminal Trove](https://terminaltrove.com/) · [Charm](https://charm.sh/)

| 作品 | 具体好在哪里 |
|---|---|
| **Yazi** | 官方示例里，父目录、当前目录、预览按阅读顺序展开。中栏文件名和靠右的大小共用一条选中底色，哪怕两者隔得远，眼睛也能沿着同一行读过去。右栏直接给内容，短列表下方的留白也很自然。[官方界面图](https://yazi-rs.github.io/webp/hostname-in-header.webp) |
| **GitUI** | Diff 图里，文件树靠缩进交代从属，当前文件靠底色定位，增删靠颜色区分。底栏直接写出在这个位置按回车会暂存当前差异块。加载提交历史的演示只在标签旁动一个字符，标题和键位仍然稳稳地待在原处。[Diff 界面](https://github.com/gitui-org/gitui/blob/master/assets/screenshots/s00-diff.png) · [加载动效](https://github.com/gitui-org/gitui/blob/master/assets/spinner.gif) |
| **Posting** | 历史为空时，它在历史栏里说明「发送一次请求，这里就会留下响应」，既解释空白，也给出下一步。进入 Jump 模式后，键位才贴到各个可跳目标旁边，平常的请求编辑界面因此能保持干净。[空历史界面](https://github.com/darrenburns/posting/blob/main/docs/assets/history/empty.png) · [Jump 模式](https://github.com/darrenburns/posting/blob/main/docs/assets/history/jump-mode.png) |
| **btop** | CPU、内存、网络各有细框，框标题嵌在线上，进程表的数值始终对着列头。即使曲线在更新，也可以盯住一个位置比较同一指标。会话台可借鉴的是让状态落在稳定的位置，尤其适合耗时和计划进度。[官方主界面](https://github.com/aristocratos/btop/blob/main/Img/normal.png) |
| **Glow** | 同一种等宽字体里，反白标题、普通正文、带左竖线的引文已经构成三级。大段正文只在需要强调的几个词上改变字重，段落空行就足以组织阅读。这比给每条内容都加粗更适合中文长标题和对话预览。[官方排版示例](https://github.com/charmbracelet/glow/blob/main/example.png) |
| **Atuin** | 搜索列表便于逐行认命令，进入 Inspector 才看到工作目录、执行耗时、退出码和前后命令。尤其好的是，用户读得出每个时间指什么。会话台同屏出现「在跑多久」和「上次活跃多久前」，正需要这种明确性。[官方 Inspector 图与说明](https://blog.atuin.sh/release-v18/) |

## 改进建议，按影响排序

### 1. 让「哪条需要我」在列表上直接可读 · 中

Gemini 深浅首图里，`blog` 下「文章页加目录，能折叠」只在远端状态列放了一个黄菱形。顶栏的「等你」又同时计算等待回复和刚做完待看的对话。用户看到 `◆2 等你`，很容易理解成有两条需要输入，实际还要再辨认一次。会话台的 `s` 汇总已经把要输入、失败、做完待看、在跑排出了先后，主界面可以直接利用这个区别。[顶栏计数口径](src/ui/app.rs:1048) · [汇总排序](src/ui/app/board.rs:102)

借 btop 的固定列和 GitUI 的就地文字提示。**宽屏状态列给需要关注的三种状态补短词**，写成 `◆ 等回复`、`✓ 待读`、`✗ 失败`，普通已停仍用 `○`。同列右对齐，宽度紧张时退回现有符号。顶栏合计改成 `◆2 待处理`，宽度允许时带出现有的 `!`；进入 `s` 汇总后沿用同一套词。这样既能扫一列找到待办，也能区分「该回一句」和「看一眼结果」。

### 2. 拉开项目、普通对话和当前对话的层级 · 小至中

Claude 图里，`shop` 和三个子标题从同一列起笔，而且都是粗体。Gemini 浅色图最明显，连续的黑色粗标题比左沿那道选中细条更抢眼。另有一个窄屏问题：代码先给账号、上下文、项目名等后缀留宽，再把余量分给标题；这些字段同时出现时，最该认出的标题反而可能只剩几个字。[组标题与对话行](src/ui/view/list.rs:545)

借 GitUI 的树缩进和 Glow 的字重分配。项目名保留现有粗体和淡色组带，**普通对话用 `title` 色常规字重，当前对话用 `title` 色粗体**；宽屏让子标题和它的动态摘要一起向右缩两格。选中时沿用贯穿标题和摘要的底色、左沿细条。窄屏先收回新增缩进，再收普通上下文、账号等后缀，目标是给标题本身保住至少 12 个终端格，约六个汉字。「只剩备份」和即将满额仍优先保留。

### 3. 给八家标签增加一档「看得懂的短名」 · 中

Gemini 首图能写出八家全名。换到有额度信息的 Claude、Codex 或 pi，其他七家就变成一串 `✻ │ ◎ │ π │ ☤ │ K │ ✦ │ ⌬`。这在 132 列的厂商图里已经发生。源码目前对五家及以上基本采用「全名放不下，就把非当前厂商一起缩成符号」的策略，所以右侧还能完整写出「2 天 23 小时后重置」，左侧却要用户记图例。[顶栏宽度策略](src/ui/view/top_bar.rs:61)

借 GitUI 标签上的可读名称。增加一个中间档，当前厂商保留「标记＋全名＋下划线」，其他家先去标记、保留短名，例如 `Claude │ ◎ Codex │ pi │ Hermes │ Kimi`。额度先收来源和正常状态下的重置长句，保住使用百分比和黄红预警；再窄才用单字符。极窄时从当前标签向两侧取能放下的邻项，边缘用 `…`，保证切到末端的 Antigravity 也看得见自己的名字。`Tab`、`⇧Tab` 和鼠标顺序都可沿用。

### 4. 把预览最上方的几行还给会话内容 · 小至中

Gemini 首图右上已经写了「在跑 · 6 分 7 秒 · 此刻的画面」，下面又写「1 条消息 · 4 分钟前 · ◐ 在跑」。同一状态出现两次，两种时间却要用户猜含义。Claude 图还有个更直观的问题：上面写「2 条消息」，下面明明能数出四段发言。Claude 适配器在这个样例里数的是两条用户发言，长文件的计数还可能只是下限。[预览元信息](src/ui/view/preview.rs:103) · [Claude 计数口径](src/sources/claude.rs:308)

借 Atuin 的详情组织。实时预览的表头写 `实时画面 · ◐ 已运行 6分07秒`，下面保留对话标题；再下一行宽度够就写 `~/projects/shop · 4分钟前活跃`，随后直接进入原始画面。历史预览有空间时再显示分支和计数；已确认统计用户发言的来源写 `你发了 2 条`，短窗口可省略计数。完整路径太长时独占一行。这样在 18 行首图里就能多看见一行实际输出，厂商原始画面的文字、颜色和换行也都能保真。

### 5. 提高浅色状态字的对比度，让慢闪只动符号 · 小

浅色图上，「别处」的柔绿比旁边普通灰字更难读。按当前主题 RGB 计算，在顶栏底色 `#E9E9E6` 上，「在跑」「等你」「别处」的对比分别约为 **3.35∶1、3.34∶1、2.73∶1**。项目的四级灰阶已有可读性检查，彩色状态文字没有得到同样的保障。Codex 深色图还截到了「等你」变灰的一拍，整个词和数字都像暂时不可用。[浅色角色值](src/ui/theme.rs:74) · [状态着色与慢闪](src/ui/view/top_bar.rs:98)

借 GitUI 加载历史时只动一个字符的做法。浅色主题可先试在跑 `#166E38`、等待 `#815800`、别处 `#466B4F`，同一栏底上分别约 **5.20∶1、5.19∶1、4.97∶1**。文字用稳定的 `muted`，符号和计数用状态色；开启慢闪时只改变 `◆` 的亮度，数字和中文保持稳定。色值集中在 `theme.rs`，继续尊重原有关闭闪烁的设置。

### 6. 矮窗口优先显示正在执行的计划步骤 · 小至中

Codex 图的 `计划 2/5` 值得保留，它比单独一个转圈更能说明任务进展。不过「补分页边界的测试」和后面两个待办都用 `□`，要靠蓝色粗体才能识别当前步。渲染还会先给计划最多五步，再把剩余高度分给现场输出。34 行图里很宽松，换到首图那样的 18 行窗口，用户最想看的测试输出就要让位。[计划符号](src/ui/activity.rs:130) · [预览高度分配](src/ui/view/preview.rs:144)

借 Glow 的字符层级和 btop 的详情排布。高窗口把三态写成 `✓ 已完成步骤`、`▸ 当前步骤`、`□ 待办步骤`，脱色仍能读懂。若展开计划会让实时输出不足四行，就收成一行 `计划 2/5 · ▸ 补分页边界的测试`。这个变化只取决于可用高度，无须用户多学一个键。

### 7. 空汇总页只提示现在能做的事 · 小

厂商没有对话时，现有界面已经会提示按 `n` 新建；搜索无结果时也会提示 `⌃A` 搜各家，这两处做得好。遗漏在 `s` 汇总页：列表已经说明没有等待或运行的对话，底栏仍会给 `⏎ 打开` 和 `! 下一条等你`。两项都没有目标。[空汇总内容](src/ui/view/board.rs:23) · [汇总底栏](src/ui/view/bottom_bar.rs:80)

借 Posting 的历史空状态。左栏保留一句 `目前没有待处理或在跑的对话`，底栏只给 `Esc 返回列表`。若有运行项但没有待处理项，就显示 `⏎ 打开` 和 `Esc 返回`。右侧可以留白，用户已经知道发生了什么、下一步怎么走。

## 取舍与验证边界

如果这一轮只做三项，我会选 **状态列补短词、拉开列表字重、顶栏补短名**。三项分别解决「谁在等我」「我选中谁」「我在哪家」，都能在用户按下回车前产生收益。浅色状态色改动很小，适合一起做。

本次核对了所给目录的 11 张假数据图、指定文档和相关渲染源码。pi、Codex 图中的 `ready` 是假 CLI 主动打印的内容，不足以判断真实预览空洞。数张厂商图底端重复出现顶栏，而主视图每帧只绘制一次顶栏；截图导出也没有完整还原下划线和删除线。因此，重复顶栏的成因、真终端里的字形和实际动效手感仍待 Ghostty 或 Kaku 验证。此次评审未改代码。[截图假数据](tests/ui_shot.rs:1674) · [截图样式导出](tests/ui_shot.rs:1182) · [主视图绘制](src/ui/view.rs:118)
