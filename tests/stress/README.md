# 压力测试（手动跑，不进 verify）

按 `docs/specs/huitai-v1.md`「测试」节的压力测试一条。起真的 `ai daemon`（release 构建，HOME 指到 `/tmp` 下的临时目录，不碰真实数据），假 CLI 是 `fake_cli.pl`（macOS 自带的 perl），从外面用 `ps`/`lsof` 量守护进程的内存（RSS）、CPU 时间、文件描述符和线程数，每项前后对比。

```sh
tests/stress/run.sh                    # 全部五项，约 32 分钟
STRESS_MINUTES=1 tests/stress/run.sh   # 先试一遍：高速输出只跑 1 分钟
tests/stress/run.sh stuck              # 只跑名字里带 stuck 的那项
```

- `STRESS_MINUTES`：20 条对话高速输出的时长，默认 30。
- `STRESS_RATE_KB`：每条对话每秒输出多少 KB，默认 1024（真实 CLI 流式输出一般每秒几 KB）。
- 每项打印 `STRESS|` 开头的数据行；断言失败即不达标。

| 测试 | 做什么 | 验什么 |
|---|---|---|
| `twenty_sessions_fast_output` | 20 条同时按速率输出（4 条一直有客户端接着，16 条没人接），期间每 2 秒 List、取快照、attach/detach 一次；结束后同一个守护进程再跑一轮 20 条 30 秒 | 客户端不被断开；每条额外内存 ≤ 15 MB；后半程内存不比前半程涨；停下后空闲 CPU ≤ 1%；重连画面和一直接着的客户端一致；全部结束后描述符、线程回到基线；第二轮后内存不比第一轮多 |
| `burst_50mb` | 一条有客户端接着、瞬间 `cat` 50 MB；一条没人接、每个字一种真彩色的 50 MB | 客户端收到的字节和输出逐字节一致；补发画面超过 16 MB 也能 attach；两次重连画面一致；结束后描述符、线程回到基线 |
| `attach_detach_200_in_a_second` | 对一条正在输出、历史满 1 万行的对话 attach/detach 200 次，三种断开方式轮流（客户端断开、Detach、被下一次 attach 接走） | 200 次在 1 秒内；之后描述符、线程回到基线；重连画面一致 |
| `daemon_kill9_then_restart` | 20 条在输出时 `kill -9` 守护进程再拉起，连做 3 轮 | 假 CLI 全部跟着退出；新守护进程认出 20 条被中断；描述符、线程和刚启动时一样 |
| `stuck_child_not_reading_input` | 一条从不读输入的，20 次 attach + 塞 256 KB + Detach；一条不读输入却一直发终端查询的 | Detach 不卡；描述符、线程不随次数涨；守护进程照常应答；Kill 后回收 |

按 `docs/specs/host-stability-tests.md` 第 2–8 项，都起真的 `ai daemon`。单独跑：`cargo test --test stress stability -- --nocapture`（数据行以 `STABILITY|` 开头）。第 1 项（透传字节 proptest）在 `tests/host_scan_prop.rs`。

| 测试 | 做什么 | 验什么 |
|---|---|---|
| `stability_big_input_arrives_byte_for_byte` | 5 MB 括号粘贴（0–255 每种字节都有）、kitty/CSI u 的 Shift+Enter 等按键、3 块背靠背的 2 MB | CLI 读到的和发的逐字节一致 |
| `stability_slow_client_is_cut_off_and_reconnects` | 一条 8 MB/s 输出、标签页完全不读；另一条有标签页照常读 | 照常读的那条每 200ms 都有新输出；List 不被拖慢；守护进程 RSS 峰值增长 < 96 MB；不读的被断开、读下去能读到头；重连画面对 |
| `stability_protocol_abuse` | 守护进程按 256 个描述符启动：会话台/订阅开了就关、随机垃圾、帧头长度离谱、半帧、连上不说话、500 个并发连接、各种请求发完就断、5000×5000 的窗口大小 | 守护进程不崩；不说话的连接 5 秒后被断开；一直输出的对话和标签页不受影响；描述符、线程回到基线；离谱的窗口大小不让内存暴涨 |

| `stability_hard_to_kill_children_are_cleaned_up` | 全家不理 SIGHUP/SIGTERM 的；CLI 收 SIGHUP 就退、子孙不理的 | Kill 后进程组清干净，不留孤儿和僵尸 |

| `stability_panic_is_isolated_and_logged` | debug 构建的故障注入：处理一条对话的输出时 panic | 这条对话接着转发、标签页不断；别的对话照常；`daemon.log` 有记录 |

## 长跑（`soak.rs`，手动跑，默认 6 小时）

```sh
tests/stress/run.sh soak                                        # 6 小时
SOAK_MINUTES=10 SOAK_SAMPLE_SECS=10 tests/stress/run.sh soak    # 先试一遍
SOAK_CSV=/tmp/soak.csv tests/stress/run.sh soak                 # 每分钟的数据另存一份
```

混合负载：6 条常驻对话一直输出（`SOAK_RATE_KB`，默认每条 64 KB/s，其中 2 条一直有标签页接着读）；每轮新开一条、接上读 3 秒并改几次窗口大小、断开再接、结束，再开一条自己马上退出的；会话台那边每 2 秒 List、取快照、订阅又关、会话台登记又关，偶尔一串垃圾连接。每分钟一行 `SOAK|分钟,RSS MB,描述符,线程,CPU%,存活堆 MB`。结束时看存活堆、描述符、线程的「地板」（最后四分之一的最小值比第二个四分之一最多高 2 MB / 2 个）；跑满 3 小时的再对后半程做最小二乘：RSS 斜率 < 2 MB/小时，描述符、线程斜率 < 2 个/小时（第 1、2 小时 RSS 还在爬到平台，短跑不看斜率）；全部结束后描述符、线程、存活堆回到基线。`tests/stress/run.sh` 不带参数时不跑它。

### v0.1.8 压力测试和 1 小时长跑（2026-11-24 15:36 – 17:09，Apple M4 Max，release，6bfd621，通过）

- 压力测试 5 项全过（exit 0）：20 条 × 30 分钟每条额外内存 5.9 MB，停下后空闲 CPU 0.00%，重连画面 20/20 一致，两轮后存活堆 0.12 MB（基线 0.10）。
- 长跑 60 个点，来去 324 轮、会话台请求 1785 轮：存活堆每 10 分钟的最低值都是 40.3 MB；RSS 57.4–67.2 MB，第 45 分钟跳 2.6 MB 后走平（后半程斜率 +8.04 MB/h，不满 3 小时不判）；描述符 30–36、线程 26–32；平均 CPU 10.0%；收尾描述符 5、线程 3、存活堆 0.11 MB（基线 0.10）。
- 输出时 CPU 平均 128%（11-21 是 93%）：同机交替各跑两遍 3 分钟，028551a 是 124.5% / 123.7%，6bfd621 是 127.4% / 126.0%，大部分是两天机器状态不同，代码只差约 2%。
- 别用 `nohup` 跑：子进程继承忽略 SIGHUP，Kill 要等满 3 秒才 SIGKILL（这次 3012 ms；去掉 `nohup` 重跑是 6 ms）。
